# Инструкция экспертам по проверке стенда

## Текущий статус

**Интерактивный ETI-стенд пока не доступен по текущей опубликованной ссылке.**
Метаданные Replit показывают публичную публикацию и успешную сборку, но
проверенный URL возвращает `404` на `/`. Путь `/eti-jury-presentation/`
открывает только презентацию, а `/api/healthz` относится к общему Node API, не к
ETI FastAPI. ETI-маршруты `/api/v1/health` и `/api/v1/sources/status` в
публикации возвращают `404`. Поэтому функциональный тест стенда с экспертом
пока не проведён; не выдавайте корневую ссылку за работающий ETI-интерфейс.

Для исправления нужен production-маршрут, который действительно обслуживает
ETI UI и FastAPI. Включать Private development URL не требуется и не следует
считать заменой публикации приложения.

Preview API использует Replit development PostgreSQL. В ней 18 технологий,
894 библиографические записи OpenAlex (названия, abstracts, авторы, даты, DOI,
ссылки) и snapshot на 2026-09-26. Полные статьи и PDF не загружались.
Пользователь разрешил использовать эти метаданные только в Preview; production
по-прежнему требует отдельной юридической проверки Source License Record.
Прежняя Docker-БД оставлена без изменений, данные между базами не переносились.

## Проверка в локальном Preview

Следующие шаги проверены только через Preview и не подтверждают доступность
опубликованного ETI-стенда.

1. Откройте Preview **ETI Jury Stand**. Главная страница должна загрузиться.
2. Проверьте блок статистики: ожидаются 18 кандидатов и 0 eligible. Evidence
   confidence не следует трактовать как ML-confidence; сейчас ни одна технология
   не проходит пороги из-за одного источника и малой reference population.
3. Выполните поиск «Технологии в ИИ». Точное название домена и варианты
   «технологии искусственного интеллекта» / «искусственный интеллект» должны
   находить технологии из текущего snapshot. Карточки ниже порогов остаются
   видимыми с явной пометкой; их нельзя считать подтверждёнными сигналами.
4. Проверьте известный alias «агентные системы» (одна технология) и доменные
   aliases «ИИ» / «AI» (18 технологий в текущей онтологии). Неизвестная тема
   должна показать пустую выдачу без фонового
   задания и без обращения к live search.
5. API-пагинация проверена с `limit=2` для 18 совпадений домена: страницы идут
   без повторов и используют одну дату snapshot. UI продолжает выдачу тем же
   `as_of_date`.
6. Откройте страницу **Источники**. Для Preview ожидается 894 записи OpenAlex;
   остальные P0-адаптеры отображаются отдельно от допуска к live-поиску.
   Статус `approved` в реестре не является юридическим подтверждением: без
   полного Source License Record адаптер остаётся заблокированным.
7. После перезапуска Preview проверьте главную страницу и health API. Для текущего
   локального запуска health endpoint: `/api/v1/health`; ожидаются `status: ok`,
    `database: ok`, `documents: 894`, `technologies: 18`,
    `latest_scoring: 2026-09-26` и
    `public_read_only: true`.

## Чек-лист эксперту после появления корректной production-ссылки

Пользователь сообщит точную ссылку эксперту после подтверждения маршрута. До
этого не используйте для функционального теста корневой production URL или
URL презентации.

1. Откройте именно ETI-интерфейс в новой сессии и обновите страницу.
2. Проверьте известный snapshot-запрос «Технологии в ИИ» и alias «агентные
   системы»; не используйте неизвестную тему, live-поиск для которой не разрешён.
3. Откройте **Источники** и убедитесь, что статус адаптера отделён от правового
   допуска; заблокированные источники должны оставаться заблокированными.
4. Проверьте health и source-status через интерфейс. Ожидаемый health должен
   явно показывать read-only режим.
5. Не отправляйте решения ревью и другие изменяющие запросы; не трактуйте
   эвристическую сортировку или evidence-confidence как ML-вероятность.
6. Передайте владельцу проекта URL, время теста и конкретные наблюдения; выводы
   об экспертной точности фиксируйте только после проверки первоисточников.

## Ограниченный локальный экспертный поиск

Публичный Preview остаётся snapshot-only: не переключайте в нём
`ETI_PUBLIC_READ_ONLY=false`. Неизвестная тема в этом режиме не запускает
задание. Для изолированной локальной проверки оператор может включить
изменяемый режим (`ETI_ENVIRONMENT=local`, `ETI_PUBLIC_READ_ONLY=false`,
`ETI_EXPERT_LIVE_SEARCH_ENABLED=true`) только на отдельной тестовой БД и с API,
привязанным к loopback. Без отдельного opt-in live-поиск выключен. Тогда непокрытая тема
может создать задание и пройти через ИИ-нормализацию запроса. Поиск выполняется
только существующими адаптерами; для каждого источника нужны `enabled`,
`approved`, `allows_derivative_analytics=true`, а также заполненные
`license_type`, `license_owner` и `license_checked_at`. Одного статуса `approved`
недостаточно. Внешние вызовы получают только варианты запроса и метаданные /
abstracts; полные тексты и PDF не загружаются.

Записи, добавленные стандартным seed-скриптом, намеренно не содержат
`license_owner` и `license_checked_at`. До заполнения этих полей после юридической
проверки источники не будут допущены к live-поиску.

Результат показывает состояние каждого источника, варианты запроса и только
категориальные сопоставления ИИ (`high` / `medium`). Это не вероятности.
Кандидаты discovery остаются review-only; при недоступности модели поиск
останавливается, а при недоступности сопоставления детерминированные кандидаты
явно помечаются как не являющиеся результатом ИИ. Не используйте для этой
проверки общую Preview-БД и не публикуйте такой режим.

Во всех режимах новые кандидаты остаются только на экспертную проверку.
Валидированная модель кандидатов пока отсутствует, поэтому ML-confidence как
вероятность не показывается. Сохраняются исходный заголовок, источник, ссылка и
дата публикации; полный текст/PDF не загружается.

## Что пока нельзя считать проверенным

- Валидность ранжирования и полноту корпуса: Preview содержит только OpenAlex,
  все 1025 маппингов ещё требуют экспертного ревью, а ни одна технология не
  проходит пороги confidence.
- Production-права на OpenAlex и материалы организаторов. Использование
  метаданных разрешено только для Preview.
- P0-адаптеры реализованы, но live-запросы не выполнялись: для источников нужны
  Source License Record с подтверждёнными владельцем и датой проверки.
- Русские резюме привязаны к цитатам исходной аннотации и помечаются как
  ожидающие проверки; они не считаются подтверждённым переводом.
- Калибровка ML-confidence не выполнена: экспертная обучающая выборка ещё
  отсутствует, поэтому значение остаётся `null`.
- Production-запуск ETI не подтверждён: текущая публикация не обслуживает ETI
  UI/FastAPI. Наличие и состояние отдельной production-БД ETI этим тестом не
  проверялись.

## Важное ограничение безопасности

API пока не имеет аутентификации. Текущий Replit Preview запускает API с
`ETI_PUBLIC_READ_ONLY=true`: операции ревью и любые другие изменяющие запросы
возвращают `403`; поиск ограничен готовым snapshot, а для запроса без совпадений
возвращается пустая выдача вместо фонового задания. Поиск по готовому snapshot
остаётся read-only. `X-Reviewer-Id` не
является проверкой личности. Этот режимный флаг не заменяет аутентификацию и
должен быть сохранён или заменён безопасной авторизацией при production-упаковке.

Текущий workspace deployment публичен, но ETI UI и FastAPI в него не включены.
Проверки без cookie показали: `/` — `404`, `/eti-jury-presentation/` — `200`
(только слайды), `/api/healthz` — `200` (общий API), `/api/v1/health` и
`/api/v1/sources/status` — `404`. Не открывайте отдельно API-порт `8000` и не
подменяйте production-проверку ссылкой на Preview.

Перед внешней проверкой также подтвердите права на материалы и одобрение
snapshot. Публичная доступность URL не подтверждает права на данные и не
добавляет аутентификацию экспертам внутри приложения.

## Результаты автоматических проверок

- Frontend: `npm run typecheck` и `npm run build` прошли.
- Backend без DB-зависимых API/review тестов: `146 passed`. Отдельный прогон
  18 адресных query/discovery проверок также прошёл; он покрывает русские
  варианты домена, alias, unknown no-match, пагинацию, OpenAlex-only local
  allowlist, происхождение карточки и запрет фонового задания в public read-only.
- Prefect flow wrapper не запускается в текущем Python runtime, поэтому шаги
  mapping, peer groups, coverage audit и scoring выполнены прямыми CLI-скриптами.
- Полный DB-зависимый backend-набор не запускался: native PostgreSQL для
  изолированных тестов не содержит `vector`. Replit Preview-БД не использовалась
  как тестовая база.
- Dependency audit, SAST и HoundDog: находок не сообщено. Эти проверки не
  подтверждают права на материалы и не заменяют проверку доступа API.

Не удаляйте Docker volume и не запускайте команды сброса базы ради проверки:
это может удалить сохранённые данные. Публикацию и выдачу публичной ссылки
для функционального ETI-теста выполняет владелец после появления корректного
production-маршрута и подтверждения прав.
